# Testing

Run the Rust and web suites with:

```sh
cargo test --all-features
cd web
npm test
npm run coverage
```

The Rust suite currently contains 402 passing tests: 85 in the dependency-free `jpeg` crate (every stage's round trip and invariants, the published Wikipedia DCT and quantization values, the Annex K Huffman codes, and encoder/decoder end-to-end cases including corrupt and hostile input) and 317 in `viz-core`. It exercises playback reduction, configuration schemas, deterministic seeded rules, geometric invariants, 2D and 3D camera behavior, serialization, type-erased dispatch, input handling, and visualization state. The separate browser-targeted WASM smoke suite currently contains 50 passing tests (33 engine smoke tests, 7 JPEG kit tests, 9 JPEG lab engine tests, and the JPEG browser-decoder oracle, which checks that Chrome decodes our encoder's files to within 3 levels per channel of our own decoder) and is run with `wasm-pack test --chrome --headless crates/viz-core` as documented in the root README.

As measured on October 4, 2026, the 375 web tests (across 30 test files) cover 91.03% of statements, 89.29% of branches, 89.55% of functions, and 91.03% of lines. They exercise the single-flight WASM loader, the shared engine lifecycle helper, the theme and token contracts, the sorting lab's summary parsing and sonification planner (against a stub AudioContext), the notes lab's theory table, log speed mapping, layout, summary parsing and voice planner (against the same stub), the gallery home's four live tiles, and representative Svelte mount and interaction paths across all four labs. Since then the web suite has grown to 1220 tests in 57 files, adding the JPEG lab's stages, share-link, summary, layout, maths and formulas modules, the R–D cache, the Huffman view data, the byte-statistics (`bytes`) and picture-catalog (`images`) modules behind the overview and gallery, and the five new stages, plus its component test against the fake engine. The lab's explain-everything cards add the pure explainers for every stage (`web/src/lib/jpeg/explain`), the canvas hit-test, the card host, placement and target action, and a coverage test (`explain/__tests__/coverage.test.ts`) that checks every target id has a card with a live number or setting, is registered in a component or the hit-test, keeps to the lab's voice, and that no native `title` tooltip or SVG `<title>` remains in the lab's own files. The lab's component test also checks that the rendered lab, the shell's transport buttons and position readout included, carries no `title` attribute and no SVG `<title>` (the shell's `nativeTitles` prop turns its own off for this lab only), that the "How it works" shout-out links to Reducible's JPEG video in a new tab, and that nested targets (the R–D dot, the sliders), touch drag slop, roving tab stops and focus return after Escape behave. The guided tour adds its step data and plain-words check, the picture maths and the latest-wins encode helper, the dialog's focus trap, keys and swipe, its portal to the page body, live region, Escape order (a showing card first), focus without scrolling and fixed button row (room kept for the longest step's words and for the slider on every step), the zoomed-in crops and the waves row's tile and waves (each at the largest whole-number scale the picture area has room for), the frame-yielding encode and the kit-failure state, and the lab's hand-off tests (including a hand-off made before the engine is ready, an upload handed back without a reload, and the lab's gallery picture picked again in the tour, which keeps the lab's block): the tour opens once on a first visit (still opens when storage throws, and stays closed for the page view when storage is full), "Show me in the lab" carries the picture and quality into the share link, and keys typed in the tour never reach the lab. The lab's component test covers the panels following the current block as the scan moves, no autoplay, and the shell's transport buttons being aria-disabled when they would do nothing (all four on the overview, Back and Reset at the first step, Play and Forward at the end); the shell's own test (`LabShell.test.ts`) covers its disabled state; and the explain-card tests (`explain/__tests__/bezel.test.ts`) cover the reason each transport card gives for those states.

Instrumentation-based Rust source coverage is currently 0% because the Cargo test gate does not configure a Rust coverage reporter. The web report's principal gaps are the Svelte components' pointer, zoom and speed-ramp paths, the pre-paint theme script in index.html, and the browser entry point. Real WebGL behavior remains outside the DOM-based unit-test environment.
